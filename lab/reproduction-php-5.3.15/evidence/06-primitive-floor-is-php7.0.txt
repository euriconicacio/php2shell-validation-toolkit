Conclusion:
- The documented CVE-2026-109618 primitive (increment nNumUsed before zend_string_init;
  zend_array_destroy walks arData up to nNumUsed) requires the PHP 7.0 "phpng" HashTable
  rewrite. Every PHP 5.x release, through the final 5.6.40, uses the old linked-list
  HashTable and does not have it. The floor for this primitive is PHP 7.0, not 5.4.0.
- The widely repeated "affects PHP 5.4+ / every PHP since 5.4" is therefore off by two
  major versions for CVE-2026-109618's demonstrated path.

Scope / caveats:
- This is the DEMONSTRATED/documented primitive. It does not prove no other OOM-bailout
  corruption path exists anywhere in PHP 5.x; the general property (OOM -> longjmp bailout)
  is present in 5.x. No source has shown an alternative 5.x path.
- CVE-2026-109619 is separate: its session.upload_progress trigger exists from 5.4.0, so
  5.4-5.6 are NOT cleared of 109619 by this analysis (only 5.3.15 is, where it is absent).
